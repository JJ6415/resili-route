# アーキテクチャ説明 (800文字以内)

【採用技術スタック】
インフラにはGoogle Cloud Run（東京リージョン asia-northeast1）を採用し、FastAPIによるサーバーレスマイクロサービスとして構築。AIエンジンにGemini 3.8 Flash、社内規程の超高速照合にVertex AI Context Caching、機密情報保護にCloud DLP、音声パイプラインにGoogle Cloud / Gemini Native TTSおよびマルチモーダルSTTを活用。交通データには公式スポンサー技術である「駅すぱあと」API MCPサーバーを直結し、フロントエンドはThree.js（3D WebGLアバター）、Leaflet（GIS地図）、Canvas（3重軌跡）で構成。

【アーキテクチャ構成と工夫】
Layer 0〜5の6階層パイプライン設計を採用。
1. コンテキストキャッシュによるコスト$0.00化：数万トークンの旅費規程や避難所DBをVertex AIに常駐化し、判定遅延とトークン消費を極小化。
2. 平時・有事のステートマシン0.1秒無停止切替：単一コードベース上で平時FinOpsからJ-Alert緊急BCPモードへミリ秒単位でUI・アルゴリズムを同期遷移。
3. 群衆ボトルネック積分の数理実装：時間依存の駅流入・流出速度からリアルタイムに過密指数を積分計算し、圧死事故を数学的根拠に基づき未然遮断。
4. Google API専任の音声・リップシンク統合：ブラウザ標準音声を排し、Gemini Native TTSの高品質WAV音声ストリームとThree.jsアバターの口形状を完全同期させ、臨場感ある管制を実現しました。
